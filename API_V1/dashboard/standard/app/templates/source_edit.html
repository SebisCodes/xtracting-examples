About this page

Where to look, what the page answers, what to collect and how often. The dashboard fetches the site only when you press Test this configuration; saving fetches nothing.

The four steps are in the order they are done, and each one opens when it can be taken. Saving, deleting and going back work at any point.

{#- THE WAY BACK, TWICE: once here and once under the save row. A watched page is a long form - four steps, a test, a picker and a save row - and the Watchlist is where a reader came from and where they go next. One link at the top is a link somebody has to scroll up to find after working their way down; one at the bottom is a link somebody has to scroll past the whole form to reach on arrival. Both is what the length of this page costs.           How often, and how gently

          {% call help_text("f-interval") %}How long the crawler waits before reading this list page again - 360 is six hours. Set it far under the rate the site really publishes at and nearly every visit finds nothing new, which is traffic the site pays for and nothing gained here.{% endcall %}
          {% call help_text("f-politeness") %}Six seconds is a visitor reading. The site's own Crawl-delay wins when it asks for more. At 0 the crawler fetches as fast as the site answers, which is how a watched page gets its address blocked.{% endcall %}
          {% call help_text("f-max-pages") %}How deep into the site's own paging one run goes before it stops. Too low and entries that have moved past the first pages are never reached; too high and every run walks the whole back catalogue of the site again.{% endcall %}
          {% call help_text("f-max-new") %}The ceiling on documents sent for extraction in one run. Each of them is extracted once per project and charged for, so this is the number that decides what a single run can cost - and the reason a first crawl of a large site does not arrive as a surprise invoice.{% endcall %}
          {% call help_text("f-timeout") %}How long one request may take before the crawler gives up on it and moves to the next address. Too short and a merely slow site is written down as unreachable; too long and one page that never answers delays the whole run.{% endcall %}

          What a crawl may follow

          {% call help_text("f-follow-pagination") %}Lets the crawler walk from page 1 to page 2 and onwards, as far as the list-page ceiling above. Switched off, only the first list page is ever read, so anything that has moved off it is never collected.{% endcall %} {% call help_text("f-same-host") %}Only addresses on the same host as the list page are collected. Switched off, a single link to somewhere else can take the crawl to a site nobody chose to watch - and what it finds there is extracted and charged just the same.{% endcall %} {% call help_text("f-drop-legal") %}They are recognised by their addresses and left alone. They sit on every page of a site and they never change, so each one collected is an extraction paid for a document nobody asked about.{% endcall %} {% call help_text("f-resubmit") %}The crawler remembers the text it sent and compares. Switched on, a corrected article is extracted a second time and charged a second time; switched off, the archive keeps the version it saw first.{% endcall %}
